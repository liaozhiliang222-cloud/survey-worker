# 第四轮：结果解释与发布验收

2026-09-05，发布候选 v0.10.0-20260905.1，包含第一至四轮的完整依赖与迁移。部署完成状态以生产验收记录为准。

## 用户可见变化

- 数据集显示有效 base、加权及收敛状态、有效样本量、所选 Sheet、来源版本和缺失口径。有效 base 是按题剔除缺失后的样本数，不等于数据总行数或加权有效样本量。
- 无可信元数据的旧结果显示待复核，不能根据缺失字段推断未加权或已收敛。
- 项目展示当前阶段与下一步建议；分别提示材料处理失败、成果生成失败、证据不足、成果待更新和报告渲染降级。
- PPT 生成前检查证据可用性和渲染边界。被排除的证据不能支持新报告；过时成果保留旧版本，可沿派生更新路径重建。
- Node 与 Pages 使用同一结果解释和准备状态服务，继续使用第二轮的任务恢复、重试和取消能力。

## 操作限制

定性报告支持可编辑 PPT。定量图表页继续明确阻止送入定性渲染器；混合报告需拆分交付。加权后继续清洗和同文件注册另一张 Sheet 仍不开放。历史结果不会因上线自动重算，参照 R1 历史结果指引复核。加权未收敛必须复核目标、迭代参数及权重分布后重新运行。

## 验收证据

- R4 业务契约覆盖新旧元数据、有效 base、收敛、证据排除、过时状态、失败及降级；浏览器覆盖 1280 和 390 宽度。
- 真实模型使用两份人工访谈，分析、大纲、脚本各一次请求，均通过来源校验；合计 3 次调用、16,960 tokens。独立于固定响应回归记录。
- 真实脚本经 OfficeCLI 生成 6 页可编辑报告。逐页视觉复查后修复原声解释与行动横条两处拥挤，复查通过。
- 生产 D1 完整备份已执行恢复排序与外键检查；在备份副本演练 0020/0021，原有记录数量及外键保持正确。R2 全部 23 个对象已保存并记录字节与 SHA-256。
- 发布前进行一次有界独立审查，无 P0/P1；补强浏览器测试以证明服务端 readiness 的有效 base 实际显示。

原始模型、报告、数据库和对象备份保存在本机 `.data/r4-*`，不进入 Git。最终干净候选回归及生产 HTTP/任务/下载验证在发布时另记。

## 发布与恢复

按 [发布流程](RELEASE_PROCESS.md) 执行。生产仅补迁移 0020、0021；数据消费者与 Pages 必须绑定同一 D1/R2。先验证备份，再迁移、部署消费者和后端，最后发布 Pages，并核对前后端 release/revision。

应用回滚不会自动撤销数据库迁移。0020/0021 为兼容性增加，优先回滚应用并保留数据；如需数据恢复，停止写入，恢复到新空库、逐行及对象校验后再切换绑定。不能将备份导入现有生产库。
