## 第一轮：修复发布候选与数据一致性

目标：让已修复代码成为可复现、可验收的发布候选。

| 任务 | 交付物 | 验收标准 |
|---|---|---|
| R1-1 整理发布范围 | 修复基线、必需新增文件及依赖/迁移清单 | 重新核对当前差异；包含共享模块和新增测试，排除临时文件；不遗漏原有未提交功能的依赖 |
| R1-2 跨格式与适配器验证 | 等价 CSV/XLSX/SAV 人工样例；本地/云端数据接口契约测试 | 相同口径下 NPS、均值、百分比和有效 base 一致；覆盖空白、真实 0、分组、等权和截尾 |
| R1-3 候选验证与回滚准备 | 完整验证日志、版本标识及恢复清单 | 按发布流程完成 Node、Python、构建及浏览器验证；测试环境核对 schema/ledger，演练备份恢复 |
| R1-4 旧结果处理指引 | 影响筛查规则、重算步骤 | 可识别需复核的缺失值、截尾和旧加权清洗结果；重算保留旧结果与来源关系 |

执行顺序：先 R1-1，再 R1-2；以验证结果形成 R1-3 和 R1-4。没有实际分析参数或运行版本证据时，将历史结果列为“需复核”，不直接宣称已确认错误。

验收：发布候选可由明确代码版本和配置重建；跨格式/适配器无未解释的统计差异；无未解决的发布阻断问题。生产发布按 [发布流程](./RELEASE_PROCESS.md) 单独执行，包含真实链路验证，不必等待后三轮全部完成。本地迁移通过不能替代生产 schema 核验。

## 第二轮：元数据与长任务可靠性

目标：样本变换后语义不丢失，长任务中断后不永久停留在运行状态。

1. **R2-1 元数据保真**：统一变量/值标签、缺失规则、Sheet、来源版本与权重状态；重点验证 SAV 的 Q 编码 NPS 题经清洗后仍可正确识别。交付变换前后对照测试。
2. **R2-2 任务终态与重试**：增加心跳/租约、过期识别、幂等键、重试和取消语义。取消后不得继续发布结果，重复请求不得生成第二份派生数据。
3. **R2-3 刷新与中断恢复**：接口返回可恢复状态，前端接入必要的恢复与重试；模拟进程退出、网络断开和执行超时。
4. **R2-4 执行与存储演练**：测量解析和大数据任务耗时，据此决定持久队列范围；验证文件缺失与部分写入。历史孤立文件先输出只读清单，清理另行安排。

验收：关键故障注入用例全部通过；同一幂等请求至多产生一份有效结果；原始数据不被覆盖；任务可恢复或进入明确可重试终态；本地/云端契约一致。恢复必须有实际执行机制，不能仅记录状态或依赖 `setImmediate/waitUntil` 的一次内存调度。

## 第三轮：证据到报告的真实交付验收

目标：证明结果可以从材料追溯到证据，并形成可用交付。

1. **R3-1 验收材料与覆盖表**：准备定量、定性、混合三套人工或脱敏授权材料，明确每套预期成果。定量覆盖分析结果/Excel/Evidence，定性覆盖可编辑 PPT；混合材料先确认渲染边界，缺口单独列项，不默认所有报告类型都支持导出。
2. **R3-2 完整链路**：使用真实测试存储和渲染器，验证材料 → 数据/访谈 → 确定性结果 → Evidence → 大纲 → PPT Script → 支持的报告输出。固定模型响应保障稳定回归，再以明确预算进行真实模型验收。
3. **R3-3 证据变更传播**：增加数值追溯、原声一致性断言；证据排除或数据重算后，标记受影响成果“待更新”，保留旧版本并提供派生更新路径。
4. **R3-4 导出与浏览器验收**：检查长原声、密集页面、分群和续排，做逐页视觉抽检；验证渲染降级提示、真实 SSE 中断和 Service Worker 跨版本升级。

验收：覆盖表内各交付路径通过；关键数值和原声与来源一致；无关键内容截断；失败原因及恢复路径清楚。真实模型、存储和渲染验收与 mock 回归分开记录。

## 第四轮：结果解释与局部维护

目标：让用户看懂结果口径和当前状态，减少重复逻辑。

1. **R4-1 结果说明**：统一展示有效 base、加权/收敛状态、来源版本、缺失口径和所选 Sheet。
2. **R4-2 项目与报告操作**：完善项目阶段、下一步操作和生成前检查；区分证据不足、待重算、渲染降级和生成失败。第二轮已实现的恢复按钮不重复开发。
3. **R4-3 局部整合**：仅把本轮触及的 Node/云端重复逻辑移入共享服务，为导入、数据及报告动作补齐契约；不整体重写旧版 `app.js`。
4. **R4-4 文档收口**：同步操作限制、状态解释、发布与恢复流程。已修复的 Vite 启动说明仅核对，不重复实现。

验收：用户可从页面判断是否加权、是否收敛和是否需更新；主要路径在移动端可用；共享逻辑变更有业务回归覆盖。

## 暂缓与条件性任务

- 原生多 Sheet 多数据集：需要文件/Sheet 去重、存储约束和 UI 选择的独立方案；当前继续使用独立文件上传。
- 加权后继续清洗：涉及重新校准和权重审计，当前继续清洗来源版本后重新加权。
- 新增模型渠道、全面视觉重做和更多分析菜单：排在可靠性和交付验收之后。
- 若决定开放给不同客户，账号与项目隔离升级为上线前置条件，单独估算；当前匿名共享工作区不能被视为多租户方案。此项不包含在上述 13–19 天中。
