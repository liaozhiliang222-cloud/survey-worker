# SurveyKit UI/UX 优化计划（2026-10-28）

走查对象：线上 https://surveykit.cc（`v0.14.0`），桌面 1440px 与手机 375px。
关联文档：`docs/PRODUCT_REVIEW_2026-10-28.md`（在 `codex/research-login` 分支）。本计划对应其中迭代 2 的“首次体验与信息架构”，并补充交互与视觉层面的问题。
旧方案 `codex-temp/UIUE_Optimization_Plan.md`（2026-07）以代码架构为主，例如拆分 HTML、合并 CSS 变量。其中的色彩、字号建议并入本计划第 4 阶段，其余架构项不在本计划范围内。

## 1. 结论

功能完整，视觉风格也已统一为“深蓝侧栏 + 浅色卡片”。主要问题不在“好不好看”，而在三处：

1. **操作后不知道发生了什么**：点了按钮没反馈，按钮灰了也不说为什么。
2. **同类事情在不同页面做法不一样**：导入数据、主按钮、帮助入口、页面命名，每个工具各有一套。
3. **样式是逐页堆出来的，没有统一规范**：颜色、字号、圆角都没有约束，每做一个新页面就更不一致。

建议顺序：先修第 1 类（见效最快、风险最小），再统一第 2 类的交互模式，最后用设计规范收敛第 3 类，避免越改越乱。

## 2. 走查范围与方法

- 逐个打开侧栏的 25 个入口，统计每页高度、按钮数、主按钮数、输入项和帮助入口。
- 抽查 5 个页面的文字对比度、小字号和无名称按钮：总览、交叉表、PPT 报告、AI 方案、数据清洗。
- 在交叉表页实际完成一次“载入示例 → 生成全部题目表”。
- 手机端（375px）与平板（768px）：顶栏、导航抽屉的展开与关闭、工具页首屏。
- 统计 `styles.css`（8499 行）中的颜色、字号、圆角、阴影和断点种类。
- 未覆盖：AI 生成类功能的完整流程、PPT 导出结果、真实用户可用性测试（列入第 6 节）。

## 4. 设计原则（本产品）

用户是做项目的研究员，主要在电脑上使用，数据密集，经常在工具之间来回切换。由此定下几条原则：

1. **每页一个主操作**，并且始终可见。
2. **每次操作都有结果**：生成就展示，导出就提示文件名，失败就说明原因和下一步。
3. **同一件事同一种做法**：导入、步骤、结果、导出、帮助在所有工具里长得一样。
4. **信息密度服务于判断**：表格和数字可以密，但说明文字和标签不低于 12px。
5. **桌面优先，平板可用**，手机只保证能查看、不出错。

## 5. 分阶段计划

### 阶段 1：快速修复（约 1 周）

不改布局，只补反馈和修错误，可以单独发布。

- F1：生成交叉表后在按钮旁显示结果卡片，写明“已生成 3 题 · 已下载《xxx.xlsx》”，提供“再次下载”和“预览前 N 题”；同时弹出提示消息。把按钮文案改为“生成并下载全部题目表”。
- F2：统一“不可用原因”组件。禁用按钮旁或悬停时说明缺什么，例如“先导入数据”，并提供跳转。
- F3：引导改为 3 步，与工作台一致：新建或导入 → 推荐下一步 → 侧栏工具库。
- N2：统一导航名、页面标题和浏览器标题，建立一张命名表，作为后续文案的唯一来源。
- H1：删除 `@media (max-width: 560px)` 中与导航相关的旧样式（`.nav`、`.nav-group`、`.nav-group.collapsed .nav-group-items`、`.nav-group-toggle`、`.nav-phase`、`.nav-item`），让手机抽屉沿用平板的竖向分组布局。改动小，但修好的是所有手机用户都会碰到的问题，建议最先做。
- H4（先做最小改动）：手机上隐藏面包屑那一行，把页面标题卡压缩为一行。顶栏已经显示页面名，再加一个返回按钮即可。
- H5：手机上把步骤条改为“第 1 / 3 步 · 导入与识别”的紧凑形式。
- 验收：5 个核心页面的每个主按钮点击后，3 秒内在视口内有可见反馈；所有禁用按钮都有原因；375px 下导航抽屉没有竖排文字和横向溢出，工具页第一个输入框出现在首屏上半部分。

### 阶段 2：统一交互模式（约 2 周）

先做 5 个共用组件，再替换到使用最多的 6 个工具上：交叉表、数据清洗、PPT 报告、AI 方案、AI 问卷、样本量。上线埋点后按真实使用率调整。

| 组件 | 规则 |
|---|---|
| 导入区 | 拖拽或点击上传为主；“粘贴文本”“下载模板”“示例数据”收进次要链接；导入后显示文件名、行列数和“更换”按钮 |
| 步骤条 | 已在交叉表、PPT 页使用，统一样式和状态（未开始 / 进行中 / 完成 / 有问题） |
| 结果区 | 先预览、后导出；导出后提示文件名和内容 |
| 页面操作栏 | 长页面底部固定一栏，放唯一的主按钮和 1–2 个次要按钮 |
| 帮助入口 | 标题旁统一放“?”，打开右侧说明抽屉，不再跳转到单独的帮助页 |

- M2：按“每页一个主按钮”重排按钮层级。
- N4：总览页在空项目时只显示“开始”区（新建 / 导入问卷 / 导入数据 / 打开示例项目）；有项目后再显示档案、资产和流程，并去掉重复的“建议下一步”和“项目档案”。
- 验收：新用户在 10 分钟内完成“导入示例数据 → 拿到交叉表 Excel”的比例 ≥ 80%（5 人测试）。

### 阶段 3：导航与信息架构（约 2 周，依赖产品决策）

与产品计划迭代 2 合并实施，需要先确认 AI 研究员和“AI 方案 / AI 问卷设计”的关系。

- 侧栏一级只保留：项目、AI 研究员、工具库、设置。工具库按“调研前 / 调研中 / 调研后 / 专项模型”分组，支持搜索。
- 去掉“研究模型”总页与子入口的重复，只保留一种进入方式。
- 工具页顶部显示“当前项目”，并能切换，减少回总览的次数。

**手机端导航重做**（与上面的信息架构一起设计，抽屉和桌面侧栏共用同一份菜单数据）：

| 区域 | 方案 |
|---|---|
| 顶栏 | 左：菜单图标（线性 SVG，替换“☰”）；中：当前页面名；右：当前项目名缩写，点击切换项目。高度 52–56px，滚动时保持固定 |
| 抽屉头部 | 品牌 + 关闭按钮；下方是当前项目卡片和“搜索工具”输入框 |
| 抽屉主体 | 一级 4 项（项目 / AI 研究员 / 工具库 / 设置）。工具库按阶段分组，默认只展开当前页面所在的分组，其余折叠，目标是不滚动就能看到全部一级入口和当前分组 |
| 抽屉底部 | 帮助 / FAQ、版本号 |
| 尺寸 | 抽屉宽 `min(86vw, 320px)`；所有可点击项高 ≥ 44px，文字 ≥ 14px |
| 底部标签栏 | 暂不做。研究员主要在电脑上使用，等埋点数据显示手机访问占比超过约 15% 再评估“项目 / AI 研究员 / 工具 / 我的”四项底栏 |

- 验收：375px 下打开抽屉后，不滚动即可看到 4 个一级入口和当前分组；从任意工具页到另一个工具页 ≤ 3 次点击（打开菜单 → 搜索或展开分组 → 点击）。

### 阶段 4：设计规范与视觉收敛（2–3 周，可与阶段 2、3 并行）

| 维度 | 现状 | 目标 |
|---|---|---|
| 颜色 | 407 种 | 约 30 个变量：品牌色、中性灰 8 阶、成功 / 警告 / 错误 / 信息各 3 阶 |
| 字号 | 43 种，最小 9px | 6 级：12 / 13 / 14 / 16 / 20 / 28，最小 12px |
| 间距 | 大量写死 | 4 / 8 / 12 / 16 / 24 / 32 |
| 圆角 | 35 种 | 4 / 8 / 12 / 圆形 |
| 阴影 | 45 种 | 3 级 |
| 断点 | 十几个 | 3 个：1200 / 900 / 600 |
| 焦点框 | 28% 透明度 | 不透明品牌色，2px，对比度 ≥ 3:1 |

- 新增 `stylelint`：禁止在新代码中写死颜色和字号，存量页面按改动顺序逐步迁移，不做一次性大改。
- 建一个“组件样例页”（仅开发环境），集中展示按钮、表单、导入区、步骤条、结果区、提示消息，作为设计和开发的对照。

### 阶段 5：持续验证

- 每个阶段结束做一次 5 人可用性测试，用固定的 3 个任务：新建项目并导入问卷、导入数据得到交叉表、生成 PPT 报告。记录完成率、耗时和卡住的位置。
- 上线埋点后，用漏斗数据决定下一批要改的页面。

## 6. 指标

| 指标 | 现状 | 目标 |
|---|---|---|
| 主按钮点击后无可见反馈的页面 | 至少 1 个（交叉表） | 0 |
| 无原因的禁用按钮 | 10+ 处 | 0 |
| 小于 12px 的文字 | 70 处 | 0（表格内数字除外） |
| 颜色 / 字号种类 | 407 / 43 | ≤ 40 / 6 |
| 空项目总览页高度 | 约 3 屏 | ≤ 1 屏 |
| 手机导航抽屉竖排文字 / 横向溢出 | 有 | 无 |
| 手机工具页第一个输入框位置 | 442px（首屏 54%） | ≤ 首屏 40% |
| 3 个固定任务的完成率 | 未测 | ≥ 80% |

## 7. 暂不做

- 深色模式：用户以办公场景为主，收益低于一致性工作。
- 更换整套图标库：先统一现有图标的用法，去掉按钮里的 emoji，后续再评估。
- 页面结构整体重写或换框架：按阶段 2 的组件逐页替换即可。
