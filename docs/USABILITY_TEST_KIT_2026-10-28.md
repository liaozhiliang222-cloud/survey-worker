# SurveyKit 可用性测试材料包

日期：2026-10-28 · 对应 UI/UX 计划阶段 5（`docs/UIUX_PLAN_2026-10-28.md`）

本材料包用于 5 人可用性测试，每轮改版结束后重复测一次，3 个任务固定不变，便于前后对比。测试前已用同一套材料在本地完整走过一遍（见第 9 节）。

## 1. 目的

回答三个问题：

1. 新用户能否不经讲解完成 3 个核心任务？
2. 在哪一步卡住、卡多久、怎么描述自己的困惑？
3. 阶段 1–4 的改动（空项目开始区、导入区、步骤条、工具库搜索、焦点框与字号）是否真的减少了卡顿？

通过标准（来自计划第 6 节）：每个任务完成率 ≥ 80%（5 人中至少 4 人不求助完成）。

## 2. 参与者

| 项 | 要求 |
|---|---|
| 人数 | 5 人：3 名没用过 SurveyKit 的新用户，2 名用过的老用户 |
| 画像 | 市场研究员、用户研究员或做过问卷分析的产品 / 运营；近半年做过至少一个问卷项目 |
| 排除 | SurveyKit 团队成员、参与过本轮设计的人 |
| 设备 | 参与者自己常用的电脑（Windows / macOS 均可），Chrome 或 Edge 最新版，屏幕宽度 ≥ 1280px |
| 时长 | 每人 40 分钟：说明 5 分钟、任务 25 分钟、问卷与访谈 10 分钟 |

## 3. 准备

- 测试地址：线上 `https://surveykit.cc`（任务 3 依赖线上报告服务，本地开发环境没有）。
- 每位参与者开一个**无痕窗口**，确保没有旧项目、没有看过新手引导。新手引导弹出时让参与者自行处理，不要替对方关掉，这一步也是观察内容。
- 材料放在参与者电脑桌面，文件夹名“测试材料”：
  - `docs/usability/示例问卷-宠物饮水机.txt`（6 题、22 个选项）
  - `docs/usability/示例数据-宠物饮水机.xlsx`（200 份合成数据，12 列，与问卷对应，不含真实个人信息）
- 记录表：`docs/usability/记录表.csv`（用 Excel 打开，每人 3 行）。
- 录屏和录音需征得参与者同意（第 8 节的口头说明），只保存在团队内部，测试报告中用 P1–P5 代称。

## 4. 主持人开场（照读）

> 感谢你来帮忙。今天测的是网站，不是你，所以没有对错。请一边操作一边说出你在想什么，比如“我在找……”“我以为点这里会……”。遇到卡住的地方，先按你自己的方式尝试；实在做不下去可以说“我放弃”，这同样是有用的结果。我会尽量不回答操作问题，因为想看到你独自使用时的真实情况。我们会录屏和录音，只用于内部改进产品，可以吗？

## 5. 任务

每个任务把任务卡打印出来交给参与者，主持人不念 UI 上的词（例如不说“导入”“交叉表分析”），避免提示路径。

### 任务 1：建项目并放入问卷

> 你刚接了一个“宠物饮水机”调研项目，客户已经给了问卷稿（桌面“测试材料”里的文本文件）。请把这份问卷放进 SurveyKit，让它成为这个项目的问卷。

- 完成标准：项目页的问卷稿里出现“宠物饮水机”问卷内容。
- 最短路径（2 步）：项目页点“导入问卷”并选择文件 → 点“确认导入”。
- 时间上限：5 分钟。
- 观察点：是否找到“导入问卷”；选文件后是否注意到预览（题量 6、选项 22）；是否知道还要点一下确认；是否去找“保存”。

### 任务 2：用数据得到交叉表

> 问卷已经回收了 200 份，数据在“测试材料”的 Excel 文件里。请得到一份按问题汇总的交叉表 Excel 文件，交给你的同事。

- 完成标准：浏览器下载了“示例数据-宠物饮水机-交叉表.xlsx”。
- 最短路径（4 步）：侧栏工具库搜索或展开“调研中” → 交叉表分析 → 上传数据 → 生成并下载全部题目表。
- 时间上限：8 分钟。
- 观察点：从项目页如何找到交叉表（搜索 / 展开分组 / 首页卡片）；是否被“粘贴 CSV”文本框吸引；生成后是否知道文件已下载（提示消息、结果卡）。

### 任务 3：生成 PPT 报告

> 同事看了交叉表，希望你再出一份 PPT 报告。请用刚才下载的交叉表生成一份 PPT 并下载。

- 完成标准：下载到 .pptx 文件。
- 最短路径（5 步）：工具库找到“PPT 报告生成” → 上传交叉表 → 解析维度 → 预览 → 生成并下载。
- 时间上限：10 分钟（包含等待生成的时间）。
- 观察点：是否理解“解析维度”“人群”“预览页面计划”这些词；等待生成时是否有焦虑或重复点击；下载后是否打开检查。
- 如果参与者在任务 2 没拿到交叉表，主持人提供 `tests/fixtures/imports/standard-crosstab.xlsx`，记录为“使用备用文件”。

### 每个任务结束后问一句（单题易用性，1–7 分）

> 总体来说，完成这个任务有多容易？1 = 非常难，7 = 非常容易。

## 6. 结束访谈（5 分钟）

1. 刚才哪一步最让你犹豫？当时你以为会发生什么？
2. 如果明天真的要做这个项目，你会用 SurveyKit 的哪部分，不会用哪部分？为什么？
3. 左侧菜单里，你觉得“AI 研究员”和“AI 方案设计”有什么不同？（检验阶段 3 的分工说明）
4. 还有什么想补充的？

## 7. 记录与分析

记录表各列：参与者、新 / 老用户、任务、结果（完成 / 求助后完成 / 放弃）、耗时（秒）、求助次数、卡住的位置、原话摘录、易用性评分、问题严重度、备注。

问题严重度：

| 级别 | 含义 |
|---|---|
| 4 致命 | 导致任务放弃 |
| 3 严重 | 卡住超过 1 分钟或需要求助 |
| 2 中等 | 犹豫、走错路后自行纠正 |
| 1 轻微 | 措辞、视觉上的疑问，不影响完成 |

测试结束后 2 天内出报告，结构固定为：

1. 3 个任务的完成率、平均耗时、平均易用性评分，与上一轮对比。
2. 问题清单：按严重度排序，每条写清出现人数（如 3/5）、发生位置、原话、建议改法。
3. 下一轮要改的 3–5 个问题，写回 `docs/UIUX_PLAN_2026-10-28.md`。

## 8. 同意说明（口头确认即可）

本次测试会录制屏幕和声音，仅用于 SurveyKit 团队内部改进产品，不对外公开，报告中不出现你的姓名。你可以随时停止，不需要说明原因。

## 9. 试测记录（2026-10-28，本地，自动化脚本代替参与者）

用上述材料按最短路径走了一遍，发现并当场修复了 3 个问题：

| 问题 | 严重度 | 处理 |
|---|---|---|
| 空项目时点“导入问卷”选好文件后，预览和“确认导入”按钮看不到。原因是阶段 2 把空项目的项目档案区收起了，导入预览在里面 | 4（任务 1 无法完成） | 导入后自动展开项目档案区并滚动到预览 |
| 导入问卷后预览显示“选项行：0”，实际有 22 个选项（只统计了 A. B. 开头的行，没统计 1. 2. 开头的） | 2 | 改为按解析结果统计，显示“选项：22 个” |
| PPT 报告服务连不上时提示“解析失败：解析失败” | 3 | 显示“报告服务暂时连不上（502），请稍后重试，已选的文件无需重新上传”；断网时提示检查网络 |

另确认：任务 2 下载的交叉表可以直接作为任务 3 的输入，结构诊断识别为“标准交叉表、11 道题”。任务 3 的解析与生成依赖线上报告服务，本地未走通，需在线上测试时确认。

自动化：`tests/e2e/usability-task-paths.spec.js` 按最短路径执行任务 1、2，只用用户可见的点击和文件选择，并限制操作次数（任务 1 ≤ 3 步，任务 2 ≤ 5 步）。以后改版若让路径变长或某一步不可见，这个测试会先失败。

## 10. 埋点（待决定，未实施）

计划中“上线埋点后用漏斗数据决定下一批要改的页面”。目前产品没有任何使用统计。需要先决定是否采集、采集到哪里。建议方案：

- 只记匿名事件，不记文件内容、文件名、项目名、问卷文本和任何个人信息；不设跨站 Cookie。
- 事件写入 Cloudflare Workers Analytics Engine（与现有 Cloudflare 部署一致，按量免费额度足够），由一个新的 `/api/events` 接口接收。
- 隐私说明中补一句“我们会统计匿名的功能使用次数，用于改进产品”。
- 首批 10 个事件，覆盖 3 个任务的漏斗：

| 漏斗 | 事件 |
|---|---|
| 任务 1 | `questionnaire_import_started`、`questionnaire_import_applied`（附带题量） |
| 任务 2 | `crosstab_data_imported`（附带行列数）、`crosstab_generated`（附带题数） |
| 任务 3 | `pptx_file_uploaded`、`pptx_parsed`、`pptx_previewed`、`pptx_downloaded` |
| 通用 | `view_opened`（页面 id）、`nav_search_used`（是否命中） |
