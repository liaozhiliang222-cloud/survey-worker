# 问卷设计第一批质量改造

生成和对话修订使用同一组设计规则；结果页、Word和Markdown附带由程序实际运行的检查结果。未提供来源的条件保持待确认，不能把模型自行写出的“通过”当作验收。

## 运行入口

- `questionnaire-quality.js` 是浏览器经典脚本及模块化入口共用的纯规则模块，可在Node中直接测试。
- `app.js` 中的生成和修订在保存输出前执行 `finalize`，并保存本次输入快照。修订引用初次生成的需求及后续修改要求，不读取后来未提交的表单变化作为原始依据。
- `src/modules/ai-questionnaire/index.js` 使用相同的设计约束、本地备用甄别和检查模块。
- `index.html`、Vite运行时资源清单及Service Worker包含新增资源，支持源码静态托管及生产构建。

## 样本条件记录

生成模型在正文之外输出一个 `questionnaire-rules` JSON代码块，不向受访者显示。`version` 为1，包含 `rules` 与 `routes` 数组。

每条规则包含：

- `id`：唯一规则ID。
- `kind`：`eligibility`（入组）、`quota`（配额）、`segment`（分群）或 `quality`（质量信号）。
- `status`：`confirmed`、`proposed` 或 `pending`。
- `condition`：条件说明；`questionIds`：相关题目。
- `source`：`field` 与 `quote`。支持的字段为 `brief`、`audience`、`constraints`、`revisionInstruction`。未确认的条件可以为 `null`。

每条分流记录包含 `id`、`ruleIds`、`entry`、`exit`、`next`。分流资格只能引用入组规则；检查引用题号、入口出口顺序和条件来源。没有分支时允许空 `routes`，但仍须记录入组定义。

已确认状态不由模型声明直接生效。程序要求引用确实存在于该字段原文，关联题目存在，并拒绝用主题性原文支持额外的年龄或行业排除。引用存在不等于条件含义正确，结果页始终保留人工复核状态。

## 检查与交付行为

检查覆盖无依据硬筛选、健康管理场景中的弱行为资格、按关注度分流、时机题与多少量表错配、常见双重问题、自评认知、排他项、单题注意力剔除、需要证据的概念表述、重复题号、无效引用和分流记录。

问题包含代码、严重度、题号、原文证据和建议。没有命中时显示“待人工复核”，不承诺全面通过。原问卷的勾选自查降为待复核，程序报告在每次修订后替换，不重复累积。

复制、Word和Markdown允许保存待修改初稿，并保留检查结果。存在需修改或待确认事项时禁用平台格式导出，同时在导出函数内检查，避免绕过按钮直接调用。通过当前规则检查后的平台格式移除系统报告和内部JSON。

本地备用稿不自动设置年龄、行业或参调排除，不把无设备购买等同于不合格；保留本人、家庭、停止使用及潜在状态，明确资格尚待项目化确认。

## 验证方式与边界

- `npm run test:ai-questionnaire`：既有问卷功能检查和新增规则回归。
- `npx playwright test tests/e2e/questionnaire-quality.spec.js`：模拟模型响应，验证生成、修订、导出、手机布局和模块化入口。
- `node tests/build-runtime-assets-smoke.mjs`：生产构建与运行时资源检查。

本轮规则针对明确的结构错误与典型措辞风险，不能全面理解自然语言，也不能证明受访者真实身份、衡量实际漏筛/误筛率或代替真实试访。浏览器测试使用模拟AI响应，不代表真实模型每次都会遵循设计要求。无JSON或JSON无效的历史问卷仍可审阅，但条件来源和分流显示待确认。
