# SurveyKit 仓库审查与产品迭代计划

审查日期：2026-09-30。产品方向：优先提升调研人员工作效率与报告质量。

同日补充：第 10 节评估旧 AI 报告的合并与退出，提出 B02/B03/B06 调整建议，并校准 F01 的影响范围。尚未执行功能下线。

## 1. 产品判断

SurveyKit 已覆盖方案、问卷、清洗、加权、交叉分析、专项模型、AI 研究员和可编辑报告。下一阶段的主要价值是让这些能力共用可信的数据版本、可恢复的项目资产和一致的交付检查。

建议按“修正数据与报告口径 → 保存问卷工作成果 → 统一报告交付 → 复用分析过程”推进。已有任务恢复、证据追溯、问题页修复和模板能力应直接复用。

核心成功指标建议采用：**一个项目从材料导入到研究员确认可交付报告的人工操作时间**。同时记录数据核对错误数、返工次数与刷新后的恢复成功率，防止只优化生成速度。

## 4. 审查发现

优先级：P1 为可能导致错误结果或不完整交付；P2 为影响工作恢复、效率或产品一致性。表中的“扩展”是明确的产品边界，不算现有实现故障。

### F01 / P2：遗留 PPT 导出代码过滤有效百分比

- 位置：新版 `app.js:11232`，`parseChartPercentValue()`。
- 行为：`percent <= 0 || percent >= 99.5` 返回 `null`。
- 隔离复现：`0%`、`99.5%`、`100%` 均被丢弃，`0.5%` 和 `50%` 被保留。
- 影响：该遗留函数确实会过滤有效百分比，但补充核查未找到新版页面的 PPT 导出按钮或事件绑定，故下调为 P2，不能视为当前正式 PPT 交付路径的已确认问题。详见第 10 节。
- 建议：以字段语义、缺失标记与明确值域校验确定是否有效；百分比、均值、NPS、频数分开处理，不能通过裁掉边界值美化图表。
- 验收：人工样例中 0%、0.5%、99.5%、100% 的标签和值完整保留；缺失值保持缺失；报告图表逐项与数据事实一致。

### F02 / P1：旧 AI 报告的原始数据摘要只分析前 12 题

- 位置：新版 `app.js:12118`，`summarizeCrosstabForAiReport()`；`12144` 对题目执行 `slice(0, 12)`。
- 隔离复现：13 题输入显示总字段数 13，但摘要只出现 Q1–Q12，不含 Q13。此限制属于原始数据模式；不能套用到所有交叉表/PPT 工作流。
- 影响：研究目标位于后部问卷时可能缺乏证据；摘要虽然标明“前 12 题”，用户仍缺少完整的纳入/排除控制与交付检查。
- 建议：提供分析覆盖清单；按研究目标和显式选择汇总题目；未覆盖题目及原因可见；正文只引用已生成的确定性统计事实。
- 验收：13、50、200 题测试集每题都有“纳入/排除及理由”；选择后部关键题时能进入报告；无静默截断。

### F03 / P1：同表头内容变化可能仍使用旧数据缓存

- 位置：新版 `app.js:5673`，`getWorkingCrosstabData()`；`5873` 全部题目表调用；`6601` 字段识别。
- 行为：只比较表头数量与名称，相同即返回旧 `lastCrosstabDataContext`，不比较数据内容或版本。
- 隔离复现：文本框数据为 `new`、缓存数据为 `old`，相同表头时返回 `old`。同时检查了字段识别及按钮绑定，未见该编辑路径重建缓存。
- 影响：重新粘贴同结构数据或修改样本后，全部题目表可能仍输出旧结果；单题交叉分析直接解析文本，两个入口可能分歧。
- 验证边界：已复现函数行为并核查调用链，尚未新增浏览器端到端复现，开发修复时须补上。
- 建议：以数据集 ID、内容指纹和版本作为缓存键；输入变更后明确失效，统计与报告携带相同数据版本。
- 验收：相同表头替换样本后，单题表、全题表、指标结果和报告使用同一新版本；旧成果保留并标记过时。

### F04 / P2：问卷版本与试访档案仅存在页面会话

- 位置：`questionnaire-workflow.js:118`、`questionnaire-review-ui.js:37`、`docs/questionnaire-quality-phase3.md`。
- 已有明确提示：刷新或关闭会清除会话历史；可以下载 JSON，但没有档案重新导入和项目级持久化。
- 影响：用户需要手工保存与重建工作上下文；版本/路径对应的试访记录难以连续积累。
- 建议：将现有问卷会话接入项目资产存储，先实现自动保存、恢复及档案导入；云端同步采用已有项目服务作为后续适配，不先扩展多人协作。
- 验收：刷新、浏览器重启、项目切换、存储失败均有明确行为；题序、需求快照、版本差异、路径与试访关联保持；旧稿恢复仍创建新版本。

### F05 / P2 扩展：混合研究报告不能统一交付

- 位置：`lib/research-readiness.mjs:27`；`docs/R4_RESULTS_AND_RELEASE.md`。
- 当前定性 PPT 的预检明确阻止定量数据页，这是有效边界保护；独立定量 PPT 路径已经存在。
- 影响：混合研究仍需手工合并报告，统一页码、来源脚注、主题与更新关系。
- 建议：建立统一报告页面契约，分别适配现有定量/定性渲染器，再组成一份报告；保持不支持页型的阻断与错误提示。
- 验收：定量、定性、混合三套授权或人工材料都能生成范围内的可编辑报告；每页保留数值/原声来源与版本。

### F06 / P2 扩展：同一文件不能登记多个 Sheet 数据集

- 位置：`lib/data-engine.mjs:72` 的 `registerRawDataset()`，`DATASET_SHEET_CONFLICT`。
- 当前要求拆成独立文件后上传；现有测试已覆盖拒绝行为，不应直接移除保护。
- 建议：以项目、文件版本、Sheet 标识共同去重，单独设计存储约束、任务幂等与 UI 选择。
- 验收：一份文件的两张表分别登记为两个数据集；相同 Sheet 重复登记幂等；删除其中之一不损坏另一份。

### F07 / P2：工作台与研究服务存在多份统计和状态实现

- 依据：`app.js` 与 `src/modules/*` 的过渡兼容层；另有 `lib/data-engine.mjs` / `lib/crosstab-engine.mjs` 服务端分析实现。源码中已有共享模块，但旧入口仍保留独立统计/报告逻辑。
- 风险：一处修复不自动覆盖另一入口；通过模块单测不能证明用户点击的旧路径正确。新版已经有 IndexedDB 与持久任务，因此不能将此问题描述为“完全没有存储或自动化测试”。
- 建议：只整合本轮触及的数据事实、来源版本、权重状态与结果展示，逐步替换调用，不整体重写 `app.js`。
- 验收：相同样例通过工具页和 AI 研究员产生的 base、百分比、均值、NPS 与缺失口径一致；不支持的加权检验明确提示。

## 5. 迭代路线图

估算假设：一名熟悉当前代码的开发者连续实施，研究负责人提供短周期验收反馈；包含针对性测试，不含等待真实材料、外部模型或发布窗口。合计 **24–36 个工作日**，属于范围估算，不能直接视为发布日期。每阶段结束据实调整下一阶段。

| 阶段 | 用户得到什么 | 范围与已有能力复用 | 估算 | 前置依赖 |
|---|---|---|---|---|
| S0 稳定基线 | 后续更新从一致版本交付 | 正式开发目录、线上版本核对、修复 F01–F03、补真实入口回归、更新产品状态表 | 2–3 日 | 确定当前候选基线 |
| S1 统一分析口径 | 换数据后所有结果一致；知道每条结论用的样本与权重 | 统一数据版本/缓存失效；原始数据报告覆盖清单；接入现有确定性结果和来源元数据；旧报告入口复用质量门槛 | 5–7 日 | S0 |
| S2 问卷工作成果恢复 | 关闭页面后继续版本审查与试访；档案可迁移 | 自动保存、项目绑定、版本/试访 JSON 导入、恢复校验、保存失败提示；复用现有版本差异与局部修订 | 4–6 日 | S0 的资产与项目标识约定 |
| S3 统一报告交付 | 一处审查数据、结论和原声；混合研究输出一份可编辑报告 | 统一页面/证据契约、渲染适配、跨入口质量检查、问题页导航与局部更新、交付包 | 8–12 日 | S1；复用既有锁定、局部修复与过时标记 |
| S4 复用与批处理 | 第二个相似项目减少重复映射和配置 | 分析配方保存/导入、字段变更检查、多 Sheet 独立数据集、串行批量导出与状态查看 | 5–8 日 | S1、S3 的稳定契约 |

### S0：先修正可确认的结果风险

1. 记录正式开发仓库、候选提交、Web/后端版本及已知差异。保留外层未提交修改，建立逐项迁移清单，不直接混入发布。
2. 修复 F01、F02 的默认覆盖行为与 F03 的缓存判定；S1 再完成统一口径和完整覆盖 UI。
3. 增加真实浏览器路径：导入 A → 同表头粘贴 B → 识别 → 全题表导出 → 下载回读核对；生成包含 0%/100% 的图表；后部关键题进入报告。
4. 更新旧迭代文档中的当前状态入口，避免完成项、候选项、线上项混写。

退出标准：三个缺陷的反向断言通过；原有关键测试无回归；每项都有当前运行版本证据。

### S1：让分析结果成为可复用、可核对的项目资产

建议采用现有 Dataset/AnalysisResult/Evidence 结构进行扩展，每次结果明确携带：数据集版本、题号、选项/指标、分群条件、有效 base、原始人数、加权基数、缺失规则、数值类型、结果 ID。复用现有字段命名，不另建平行事实库。

用户流程：选择项目数据版本 → 核对字段与分析题目 → 应用清洗/权重配置 → 查看覆盖清单 → 计算并送入报告。

验收：

- 等价 CSV/XLSX/SAV 在相同配置下结果一致；包含空白、真实 0、缺失码、多选、矩阵与权重样例。
- 切换 Raw/Clean/Weighted 明确显示版本、样本量和适用口径，旧成果按已有机制标记待更新。
- 全题分析覆盖 100% 已选题，排除项有原因；任务可复用现有持久执行和取消能力。
- 对于未支持的权重统计/检验明确阻止或说明，不将普通未加权结果标为加权。

### S2：补齐问卷版本与试访的持续工作流程

最小范围：自动保存状态、项目下的版本列表、关闭后恢复、JSON 档案导入与兼容性校验、试访按版本与路径回填。显示“已保存/保存失败/仅本次会话”，不能捕获存储错误后仍让用户以为保存成功。

验收：

- 连续生成和修改 10 个版本后，刷新或重启仍可恢复；非当前版本内容不可被原地篡改。
- 项目 A/B 的需求快照、问卷、路径和试访记录隔离。
- 导入不合法或不兼容档案时保留当前资产，不出现部分覆盖。
- 保留现有客户稿清理规则；研究版与客户版分别导出，试访意见不会混入客户问卷。

### S3：从报告生成升级为报告交付工作台

1. 统一报告目录：标题、核心结论、证据、图表/原声、页状态、来源版本在同一工作台可见。
2. 证据定位：点击数值打开对应结果/口径，点击原声定位访谈依据；缺证据结论保留为待验证，不能伪装成数据事实。
3. 复用现有局部修复、页锁定与撤销；新增跨类型报告中的受影响页更新。保护人工编辑页，显示冲突后再由研究员处理。
4. 混合渲染：先支持少量已验证的页面类别，例如定量对比、定性原声、综合结论；通过现有渲染器适配输出同主题 PPT。复杂或未知页型继续明确拒绝。
5. 交付包：PPT、分析结果 Excel、数据口径说明、题目覆盖清单与来源版本清单。优先复用现有 Word/Excel/PPT 导出链。

验收：

- 三套基准项目：纯定量、纯定性、混合，各跑完整交付流程。
- 所有交付数值和引用在定义的显示精度下与源证据一致；0%/100%、小样本、缺失与加权状态正确。
- 定量图表可编辑、定性文本可编辑；长标题、长原声、密集页和续页经过实际渲染检查。
- 来源数据更新后显示受影响页；不无提示覆盖用户已锁定或手工改过的内容。
- 真实模型效果另行有界评估；mock 回归通过不代表真实内容质量通过。

### S4：把做过的项目变成可复用的方法

首批配方限定在高频需求：满意度/NPS、U&A、概念测试。配方保存变量映射、标签/缺失规则、分群、权重设置、模型参数和页面规划；不把旧项目的样本数据与结论一并套用。

多 Sheet 为独立小范围功能；文件引用计数、删除保护与登记幂等必须同步实现。批处理复用现有任务执行器，先采用受控串行执行，结合服务器容量再评估并发。

验收：同结构新项目可复用配方；缺字段、量表变化和失效权重会阻止误用；批量任务可逐项重试且不重复发布成果；双 Sheet 数据集删除/重试互不影响。

### 使用流程

1. 点击“检查来源与受影响页”，逐页显示已复核、待复核、来源变化或阻断问题。数值可直接点击查看源结果；原声旁的“定位原声”沿用访谈片段定位。首次使用需要确认各页结论已经复核。

## 15. S4 实施记录（2026-09-30）

### 使用流程

5. 多 Sheet 文件先登记首张表，再使用“追加工作表”选择其他表。按项目、文件、实际工作表名去重；重试不会重复登记。页面显示同源工作表引用数量。“删除未使用工作表”只解除该表登记并保留源文件；有派生版本、分析、任务或批次引用时拒绝删除，其他工作表可继续使用。

## 16. S4 第二批：完整量表定义与字段校验（2026-09-30）

“保存分析配方”现支持为选中字段指定完整数值量表（上下限、整数或小数）或完整类别编码（每行一个），也可继续使用当前观测范围。NPS 保持固定 0–10 整数。指定范围会校验当前数据；不能用缩小范围的方法静默丢弃现有回答，不符合时保留弹窗输入并提示先核对或清洗。
